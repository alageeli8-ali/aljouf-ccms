# نظام إدارة المجالس واللجان وفرق العمل
## Aljouf Councils & Committees Management System (CCMS)

**الجهة المالكة:** المكتب الاستراتيجي لتطوير منطقة الجوف — الإدارة العامة لتقنية المعلومات والتحول الرقمي
**المرحلة الحالية:** المرحلة 2 مكتملة — المجالس واللجان وفرق العمل والعضويات والاجتماعات وجدول الأعمال والدعوات والحضور والنصاب تعمل تشغيليًا. التفاصيل في [docs/18-phase2-delivery.md](docs/18-phase2-delivery.md)، والمرحلة 1 في [docs/17-phase1-delivery.md](docs/17-phase1-delivery.md)
**حالة الوثائق:** الإصدار 1.0 — 2026-10-16

---

## الغرض

نظام مؤسسي يدير الدورة الكاملة لعمل المجالس واللجان وفرق العمل: التشكيل والاختصاصات والعضويات، والاجتماعات وجدول الأعمال والدعوات، والحضور والنصاب، والمداولات والتصويت والقرارات، والمحاضر واعتمادها، والتوقيع الاختياري، والمهام الناتجة عن القرارات ومتابعتها وتصعيدها والتحقق من إنجازها، والتقارير والأرشفة والبحث، مع وحدة ذكاء اصطناعي اختيارية تُفعَّل وتُعطَّل من لوحة الإدارة.

## القرارات الجوهرية باختصار

| القرار | الاختيار | المرجع |
|---|---|---|
| المعمارية | Modular Monolith: تطبيق واحد قابل للنشر، بوحدات أعمال مفصولة منطقيًا، ومخطط (schema) مستقل لكل وحدة | ADR-001 |
| الواجهة | React + TypeScript (Vite)، عربي افتراضي RTL + إنجليزي | ADR-007 |
| الخلفية | ASP.NET Core Web API على .NET 10 LTS بلغة C#، موثّقة بـ OpenAPI | ADR-002 |
| قاعدة البيانات | PostgreSQL 16+ (قاعدة واحدة، مخطط لكل وحدة)، وترحيلات SQL مرقّمة | ADR-003، ADR-016 |
| الدخول | Microsoft Entra ID (OIDC) بنمط BFF وجلسة HttpOnly | ADR-004 |
| الوحدات الاختيارية | التوقيع الإلكتروني، والذكاء الاصطناعي، والتكاملات: وحدات مستقلة خلف Feature Flags، والنظام يعمل كاملًا بدونها | ADR-005، ADR-006 |
| التواصل بين الوحدات | عقود عامة (Contracts) + أحداث تكامل عبر Outbox داخل المعاملة نفسها | ADR-008 |
| النشر | حاويات Docker داخل مركز بيانات المكتب أو بيئة سحابية معتمدة داخل المملكة | ADR-009 |

## العلاقة بالإصدار التجريبي 0.5

مستودع `majalis-demo` (Python/FastAPI) نموذج أولي جُرِّبت فيه قواعد العمل مع المستخدمين. هذا النظام **إعادة بناء** على التقنيات المؤسسية المعتمدة، يحمل القواعد التي ثبتت صحتها (انظر [00 §4](docs/00-index-and-glossary.md#4-ما-يُحمَل-من-الإصدار-التجريبي-05))، ويوفر مسار ترحيل لبياناته إن استُخدم بيانات حقيقية (ADR-012).

## حالة التكاملات الخارجية

لا يوجد أي تكامل خارجي جاهز في هذه المرحلة. كل تكامل مصمم كمحوّل (Adapter) خلف مفتاح إعداد، وله بديل يدوي يُبقي النظام عاملًا. التفاصيل وما يلزم لكل تكامل في [03 §7](docs/03-architecture.md#7-التكاملات-الخارجية) و[16](docs/16-assumptions-and-open-questions.md).

## هيكل المستودع

```
db/              bootstrap.sql وترحيلات SQL المرقّمة
src/backend/     ASP.NET Core: Ccms.Host + الوحدات + العقود + الاختبارات
web/             React + TypeScript (يُبنى إلى wwwroot في Ccms.Host)
deploy/          Nginx وقالب متغيرات البيئة
docs/            الوثائق ونتائج الاختبارات ولقطات الواجهة
tools/           فحص اتساق الوثائق
```

التشغيل والاختبارات: [docs/17-phase1-delivery.md §5](docs/17-phase1-delivery.md#5-التشغيل).

## التحقق من اتساق الوثائق

```bash
python3 tools/check_docs.py
```
يتحقق من أن كل معرّف مُشار إليه (متطلب، مفتاح إعداد، جدول، قرار فني، خطر) معرَّف في وثيقته، وأن كل متطلب وظيفي مغطى باختبار ومرحلة تنفيذ.
