# بيئة التجربة على GitHub Codespaces

تشغّل هذه البيئة **صورة الإنتاج نفسها** بمشغّل Npgsql، وبضوابط الإنتاج نفسها، داخل مساحة GitHub Codespaces مجانية، مع بيانات وهمية.

**الغرض:** تجربة النظام ومشاركته مع زملاء قبل خادم المكتب.

**ليست بيئة إنتاج.** التفاصيل في docs/25-operations-guide.md §11.

> ⚠️ **بيانات وهمية فقط.** الاستضافة خارج المملكة وغير معتمدة من الأمن السيبراني. لا تُدخل أسماء أو محاضر أو مرفقات حقيقية أو مصنفة.

## 1. الإنشاء (مرة واحدة، 10–15 دقيقة)

1. افتح المستودع في GitHub.
2. اضغط زر **Code**، ثم تبويب **Codespaces**، ثم **Create codespace on main**.
3. انتظر. الإعداد يعمل آليًا ويعرض تقدمه في الطرفية:
   1. توليد أسرار عشوائية.
   2. بناء صورة الإنتاج (5–10 دقائق في أول مرة).
   3. قاعدة البيانات والترحيلات.
   4. البيانات الوهمية.
   5. التشغيل.
   6. فحص الدخان.
4. في النهاية يُطبع **الرابط وكلمة المرور**، ويُحفظان في الملف deploy/trial/.trial-credentials داخل المساحة. لا يُرفع هذا الملف إلى المستودع.

**إذا فشل الإعداد:**

- افتح لوحة الأوامر (Ctrl+Shift+P)، واختر **Codespaces: View Creation Log**.
- أو شغّل في الطرفية: `bash deploy/trial/setup.sh`. السكربت آمن لإعادة التشغيل.
- أرسل آخر 50 سطرًا من المخرجات.

## 2. الدخول

| البند | التفاصيل |
|---|---|
| الرابط | الشكل https://<اسم-المساحة>-8080.app.github.dev، ويظهر أيضًا في تبويب **PORTS** بجوار المنفذ 8080 |
| كلمة المرور | واحدة لكل الحسابات، ومولدة لهذه المساحة فقط. كلمة المرور المنشورة في المستودع **لا تعمل هنا** |
| البريد | <الاسم>@sample.jsdo.test |

**الأسماء:**

| الحساب | الدور |
|---|---|
| governance | مسؤول المجالس |
| admin | مدير النظام |
| ceo | الإدارة العليا |
| chair | رئيس اللجنة |
| secretary | أمين السر |
| member | عضو |
| auditor | المدقق |
| manager | مدير إدارة |
| executor | موظف مكلف |

**سيناريو مقترح للتجربة** (24 §5): ادخل بالحسابات بالترتيب:

1. **secretary:** أنشئ اجتماعًا.
2. **chair:** راجع المحضر.
3. **executor:** حدّث مهمة.
4. **manager:** تحقق منها.
5. **ceo:** اطّلع على اللوحة.
6. **auditor:** راجع سجل التدقيق.

**لتجربة التوقيع والذكاء الاصطناعي:**

- ادخل بحساب admin، ثم افتح «إعدادات النظام».
- فعّل الوحدة، واختر المزوّد mock.
- المزوّدان تجريبيان موسومان، ولا يُنتجان توقيعًا أو تحليلًا حقيقيًا.

## 3. المشاركة مع زملاء

المنفذ **خاص** افتراضيًا، فلا يفتحه إلا حسابك في GitHub. للمشاركة:

1. افتح تبويب **PORTS**.
2. انقر بالزر الأيمن على 8080، ثم **Port Visibility**، ثم **Public**.
3. أرسل الرابط وكلمة المرور بقناة داخلية. **لا تنشرهما.**
4. أعِد المنفذ إلى **Private** بعد العرض.

**ملاحظة:** كل الطلبات تصل إلى التطبيق من عنوان داخلي واحد، فعنوان المنفذ في سجل التدقيق هو عنوان بوابة Docker، لا عنوان المستخدم.

## 4. التشغيل والإيقاف والحصة المجانية

- **الإيقاف عند الخمول:** تتوقف المساحة بعد خمول افتراضي مدته 30 دقيقة، أو يدويًا من github.com/codespaces.
  - البيانات تبقى.
  - عند الاستئناف تعود الحاويات آليًا (start.sh) خلال دقيقة.
- **أثناء الإيقاف:** الرابط لا يعمل.
- **الحصة المجانية لحساب GitHub Free:** 120 ساعة شهريًا، وتعادل نحو 60 ساعة تشغيل على جهاز بنواتين، و15 ج.ب تخزين.
  - دون وسيلة دفع مسجلة يتوقف الاستخدام عند نفادها، ولا تُخصم رسوم.
- **حذف المساحة:** يحذف البيانات الوهمية كلها. المساحات غير المستخدمة تُحذف آليًا بعد مدة الاحتفاظ (30 يومًا افتراضيًا).

## 5. التحقق بمشغّل الإنتاج (موصى به مرة واحدة)

الاختبارات الـ142 شُغّلت في التطوير بموصل مصغّر. لتشغيلها هنا بمشغّل الإنتاج Npgsql (نحو 5 دقائق):

```bash
bash deploy/trial/verify-npgsql.sh
```

- يستخدم قاعدة اختبار مؤقتة منفصلة، ولا يمس بيانات التجربة.
- يكتب التقرير في docs/test-results/npgsql-run.md.
- أرسل نتيجته (السطر الأخير).

## 6. ما يختلف عن الإنتاج

| البند | التجربة | الإنتاج |
|---|---|---|
| الدخول | محلي لكل الحسابات التجريبية | Entra ID، والمحلي للطوارئ فقط |
| المزوّدان التجريبيان (التوقيع والذكاء الاصطناعي) | مسموحان وموسومان | ممنوعان |
| البيانات | وهمية بكلمة مرور مولدة | حقيقية |
| TLS | من GitHub (رابط app.github.dev) | nginx بشهادة المكتب |
| nginx والنسخ الاحتياطي | غير مشغلين | مشغلان |
| الموقع والتوفر | GitHub، خارج المملكة، يعمل أثناء تشغيل المساحة فقط | خادم المكتب، دائم |

**ما هو مطابق للإنتاج:**

- الصورة وبناؤها.
- مشغّل Npgsql.
- PostgreSQL 16 والترحيلات.
- فصل حسابي المالك والتطبيق في القاعدة.
- مفاتيح حماية البيانات الدائمة.
- كعكات Secure.
- تصفية المضيف.
- حدود الطلبات.
- ضوابط الإقلاع.
